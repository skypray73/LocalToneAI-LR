# 每次怎麼用、完成視窗怎麼看

## 日常操作

1. 打開 Lightroom Classic 的編目。在「圖庫」選取本次照片，可以跨多個資料夾。
2. 點頂端 **「編輯(E)」→「編目設定…」→「中繼資料」**，在上方「編輯」區塊確認 **「自動將變更寫入附屬檔案 (XMP/ACR)」左邊方框空白、沒有勾號**，再按右下方「確定」。詳見 [完整中文檢查步驟](INSTALL.zh-TW.md#check-xmp)。
3. 頂端選單 **圖庫 → 增效模組額外資訊**，依需要選擇 **本地分析並套用選取照片（全部）** 或 **本地分析並套用選取照片（僅未修改）**。
4. 確認開始後，保持 Lightroom 開啟，期間不要手動切照片、改滑桿或切編目。
5. 處理結束，在「編輯相片」查看主體、亮部、陰影、膚色與黑位。

不必開聊天工具、PowerShell 或 Ollama 視窗。已依安裝說明準備好的可攜版 Ollama，會在服務未執行時由分析器在背景啟動。已有服務時沿用既有服務；它的模型位置及本地設定必須事先正確。

## 何時需要暫停操作 Lightroom？

1.13.2 起，開始前會跳出「修圖期間，請暫停操作 Lightroom」確認視窗。從開始到整批完成，請勿切換照片、切換編目、調整滑桿或再啟動其他修圖工作。可以使用其他程式，請保持 Lightroom 開啟。

| 階段 | 會顯示什麼提醒 | 何時能繼續操作 LR |
|---|---|---|
| LR 自動校正 | 第一階段進度顯示「請勿操作 Lightroom」 | 等整批完成 |
| 預覽匯出 | 進度顯示「請勿切換照片或調整滑桿」 | 自動流程須等整批完成；手動匯出等完成視窗 |
| 本地 AI 分析 | 獨立進度視窗標題提醒，並阻擋 LR 操作 | 等分析及後續套用都完成 |
| 套用修圖設定 | 進度顯示「請勿操作 Lightroom」 | 等完成視窗 |

完成視窗會明確顯示「本次流程已結束，可繼續操作 Lightroom」。手動匯出與手動套用也會先提醒暫停操作，再於完成時提示可繼續。提醒用於減少選取與設定被干擾，不是當機原因已獲證實的宣告。

需要中止時請用外掛的取消按鈕。取消或錯誤不會自動回復已完成的調整；若提示背景分析可能仍在完成，先等背景工作結束，再啟動下一批。

## 全部選取與僅未修改模式

「全部」保留原處理方式。「僅未修改」在每張呼叫 LR 自動前檢查以下六項，只有全部為 0 才進入兩階段修圖：

| 中文滑桿 | 設定鍵 |
|---|---|
| 曝光度 | `Exposure2012` |
| 對比 | `Contrast2012` |
| 亮部 | `Highlights2012` |
| 陰影 | `Shadows2012` |
| 白色 | `Whites2012` |
| 黑色 | `Blacks2012` |

任一值非零（例如曝光度 +0.01、亮部 -1）就列為「已修改略過」，不呼叫自動、不匯出、不交給模型，也不套用設定。缺少數值或非有效數字時列「數值無法確認略過」。這兩者與自動後數值未變、模型待確認、分析失敗分開計數。

此模式不看白平衡、銳利化、鮮豔度、飽和度、裁切或步驟記錄；曾修改但六項都恢復為 0 的照片仍會處理，只有其他設定改過的照片也會處理。選取全部不符合時顯示摘要即結束；可查看 `tone-check-日期時間.json` 的 `selection_mode`、`modified_skipped`、`unreadable_skipped` 和逐張原因。

## 進度顯示

第一階段在 Lightroom 左上角工作進度顯示張數，也會逐張選取照片。1.12.3 起，第二階段改用獨立的「第 2 階段：本地 AI 分析」進度視窗，約每秒更新：已分析張數／總張數、百分比、目前照片檔名、本階段經過秒數、分析失敗張數。模型載入時顯示「準備模型」，完成推論後顯示整理計畫或等待套用；檔名更新不代表 LR 選取也跟著改變。

此時照片仍在背景分析，已分析張數包含失敗照片，不是已修改照片數，也不是單張內部推論百分比。模型載入、重看臉部或重試同一張時，張數可能暫時不增加，時間仍會更新。只有到了「套用 AI 顯影滑桿」才開始套回第二階段設定；最後仍以完成視窗、實際滑桿及畫面為準。

視窗顯示時會阻擋其他 Lightroom 操作。按取消會阻止本次接續套用，背景分析可能繼續完成，已完成的第一階段設定不會自動復原。不要取消後立即再開另一批，以免同時占用本機模型。進度檔暫時讀不到時保留上次張數；也可查看該批次 `analysis.log` 和 `local-result/progress.tsv`。

## 第一階段的確認方式

1.12.2 版逐張選取、等待編輯相片控制可用，再呼叫一次 Lightroom 自動色調。控制名稱 `Exposure` 與設定鍵 `Exposure2012` 分開處理，兼容語系別名並容許顯示值四捨五入。控制值與目標相片連續兩次符合才開始；控制未就緒最多等 20 秒，仍未就緒時記錄原因、略過並繼續其他照片。

必須觀察到色調數值與執行前不同，而且連續穩定，才計入「已確認基礎校正數值變更」。

沒有觀察到變更且數值連續穩定約 3 秒，列為 **「自動後數值未變且穩定」**，直接以目前顯影設定接續第二階段，不重複呼叫自動。這解決已經按過自動的照片被整批略過的問題。已開始變動者仍等待穩定，觀察上限約 16 秒；控制未就緒或數值仍不穩定才列為未確認並略過。這些時間是外掛輪詢間隔，不是 Lightroom 整體耗時保證。

照片可能原本就等於 LR 自動結果；但數值未變仍不能證明自動成功，所以不計入「已確認基礎校正數值變更」。外掛將這類照片逐張標成 `current-develop`，讓 AI 判斷新轉存的目前預覽；有觀察到自動變化的照片標成 `after-lightroom-auto`。慢載入的照片可能在短確認窗後才更新，轉存時的 baseline 檢查會拒絕設定變動的預覽；模型判斷與套回前仍檢查目前設定，請勿在執行中切照片或改滑桿。

會保存：

- `C:\AI\LightroomJobs\tone-check-日期時間.json`：逐張執行前後數值、重試次數與狀態。
- 新批次中的 `tone-verification.json`：第一階段檢查紀錄。

先前 1.10 與更早版本只因數值穩定就計入完成，可能把一直維持 0 的照片也算成功。新版改為較保守的數值驗證；這仍不是影像品質驗證，也不能完全證明非同步 SDK 呼叫的因果關係。

## 第二階段：本地 AI 與固定偏好

對第一階段顯影數值穩定的照片（包含自動後有變化及穩定未變），重新轉存 1024px sRGB JPEG；「僅未修改」模式篩選略過者不匯出。AI 看目前預覽和臉部放大圖，提出額外亮暗增量；風景清晰度／去朦朧和人像銳利化／鮮豔度則由規則設定。套用前會比對編目、照片 ID、完整來源路徑和相關滑桿 baseline，避免套錯照片或覆蓋期間的手動修改。

## 完成數字各代表什麼？

1.13.1 的完成視窗先顯示簡短結果。以一張已做 LR 自動、只套用主體偏好規則的照片為例：

```text
已完成 1 張照片
僅處理未修改照片 · 選取 1 張

LR 自動校正：1 張
人像／風景調整：1 張
AI 本次未追加亮暗微調。

請到「編輯相片」查看效果。
```

按「完成」即可關閉；按「查看詳細紀錄」才顯示完整分類張數、快照狀態和工作資料夾路徑，關閉詳細紀錄後會回到簡短結果。全為 0 的狀態不占主畫面；有待確認、設定無法讀取、LR 校正未確認或 AI 失敗才額外列出。模型待確認與分析失敗不計入「已完成」，第一階段已發生的修改仍保留。「已完成」是流程結果，最後畫面仍需自行確認。

人像／風景調整和 AI 亮暗微調可能發生在同一張，兩者不能相加當總張數。全部被篩選略過時，改顯示「沒有需要處理的照片」，不宣稱完成修圖。

下表為「查看詳細紀錄」內保留的完整分類：

| 顯示 | 意思 |
|---|---|
| 已修改略過 | 僅未修改模式下，六項色調至少一項非零，整張未處理 |
| 數值無法確認略過 | 僅未修改模式下，無法取得完整有效的六項色調，整張未處理 |
| 已確認基礎校正數值變更 | 第一階段前後數值不同且已穩定；不是只計算呼叫次數 |
| 自動後數值未變且穩定 | 未宣稱自動成功，已用目前設定接續 AI 分析 |
| 控制／數值未確認 | 控制未就緒或數值不穩定，已略過後續處理 |
| 已套用 AI 微調 | 第二階段有額外亮暗等調整，不含固定偏好 |
| 已套用主體偏好規則 | 人像保守鮮豔度／銳利化，或風景清晰度／去朦朧 |
| 無需額外 AI 微調 | 模型沒有可套用的額外亮暗建議，可能已套用固定偏好 |
| 模型判斷待確認 | 分類、臉部光線等有不確定，未套用第二階段 |

同一張可以同時有 AI 微調和固定規則，因此這兩個張數不能直接相加當總張數。

**AI 微調為 0，不代表照片完全沒修，也不保證照片已最佳。** 目前模型有時非常保守，即使辨識出夜景，也可能讓全部亮暗增量為 0。陰影範圍放寬只是允許較大調整，不會強制模型提亮。若視覺上仍偏暗，請在 Lightroom 確認，並查看實際提案與高光保護紀錄。

## 哪些資料會寫進硬碟？

```text
C:\AI\LightroomJobs\
├─ tone-check-日期時間.json
└─ local-batch-日期時間\
   ├─ tone-verification.json    第一階段逐張前後數值
   ├─ manifest.json             編目、來源身分和分析時參數
   ├─ previews\                 本地 AI 看的小張 JPEG
   ├─ rendered\                 Lightroom 正式轉存預覽
   ├─ analysis.log              執行紀錄
   └─ local-result\
      ├─ report.json            待套用設定、規則分類與略過原因
      ├─ decisions.json         AI 判斷與量測資料
      ├─ analysis-照片ID.json    模型原始建議
      ├─ plan.tsv               外掛自動讀取的顯影計畫
      └─ presets\               可供檢查的設定檔；不寫回來源資料夾
```

`report.json` 的 `lightroom_applied`、`visual_verified` 是產生計畫時的欄位，目前不會在 Lightroom 套用後回寫，因此不能單憑這兩個欄位判斷最終是否已套用。完成視窗回報 SDK 套用呼叫；最終數值和畫面仍以 Lightroom 為準。

工作檔包含私人的照片預覽、來源路徑和編目資訊，**不要直接公開整個批次資料夾或上傳 GitHub**。排錯時先去除私人路徑和影像；本專案的公開範例與測試不用你的照片。

## 復原與清理

外掛不自動建立快照、不刪除既有快照。需要完整回復保障時，執行前請自行備份編目或建立快照。執行後可逐張透過 Lightroom「步驟記錄」回到先前狀態；它不是一個涵蓋整批的保證單次復原。

`LightroomJobs` 目前不自動清理。確認分析與 Lightroom 都沒有使用該批次後，可在檔案總管自行刪除不需要的批次和檢查紀錄。不要因此刪除原 RAW 或正在使用的編目。

## 常見狀況

| 狀況 | 先檢查 |
|---|---|
| 找不到入口 | 在頂端「圖庫」選單，不是右鍵；外掛管理員確認已啟用，更新後重開 Lightroom |
| 跑很久沒有反應 | 查看 Lightroom 進度及該批次 `analysis.log`／`local-result/progress.tsv`；模型載入、GPU、預覽轉存都會影響時間 |
| 提示本地分析失敗 | 看 `analysis.log` 和 `failures.json`；確認 Qwen 標籤、Ollama、Python 依賴與 YuNet 檔案 |
| 基礎校正未確認 | 查看 `tone-check-*.json`；先選少量、未調整照片重跑，對照按 LR 自動後的實際滑桿；勿把未確認算成功 |
| 原始建議有調整，最後沒套用 | 檢查低信心／待確認、滑桿界限、高光保護及 baseline 不一致 |
| 夜景仍太暗但 AI 都為 0 | 這是目前模型可能過於保守的限制，不能只憑完成視窗宣稱畫質達標 |
| 人像待確認 | 臉太小、候選皮膚區域不足、光線意圖不確定或多人明暗衝突；請手動查看 |

單張時間沒有保證值：初次載入模型較慢，人臉矛盾可能重看一次；第一階段每張只呼叫一次自動，模型回覆失敗才有一次重試。GPU 推論測試不代表整批端到端速度。取消或錯誤時，第一階段已發生的修改不會自動回復，請依視窗及步驟記錄檢查。

## 單張模型失敗與舊批次救回

1.12.0 起，單張模型回覆不完整、JSON 無法解析或連線暫時失敗，最多重試一次。第二次給較大的回覆長度；仍失敗就記入 `failures.json` 並繼續。成功且通過檢查的計畫照常套用，完成視窗另列「分析失敗」張數。待確認、無需微調和分析失敗分別計數。服務完全不可用時，逐張等待重試仍可能很久；重試不是無限等待或必定成功的保證。

舊版可能已跑完所有分析，卻因一張失敗而擋住整批套用。先看 `analysis.log` 最後是否已有 `Complete` 及 `local-result/report.json`，不要直接重做第一階段。維護用工具可保留原結果，只對 `failures.json` 的照片使用既有預覽重試，產生新的計畫；不控制 Lightroom、不建立完成標記，也不覆寫原結果。

在 PowerShell 執行（把批次名稱替換成你的實際資料夾；若 Python 在其他位置，改成相應執行檔）：

```powershell
& 'C:\AI\LightroomLocalDevelop\.venv\Scripts\python.exe' `
  'C:\AI\LightroomLocalDevelop\scripts\resume_failed.py' `
  --batch 'C:\AI\LightroomJobs\local-batch-日期時間' `
  --out 'C:\AI\LightroomJobs\local-batch-日期時間\local-result-recovered'
```

新資料夾必須不存在；舊批次已有 `local-result.tsv` 時工具會拒絕，避免重複處理。重試仍失敗者不納入計畫。

救回後重開 Lightroom、開啟原編目、選取原批次照片，再按 **圖庫 → 增效模組額外資訊 → 將修圖計畫套用至選取照片（手動）**，選新資料夾中的 `plan.tsv`。這一步才真正套用第二階段，不重做 Lightroom 自動。若照片在分析後又改過，baseline 檢查會擋下；不要跳過檢查或直接重複套用。原本已套用部分照片的批次應先逐張核對，不能拿這個工具當通用續傳按鈕。

## 手動選單用途

- **匯出選取照片供分析（手動）**：只建立目前顯影預覽，不自動執行第一階段。給熟悉命令列的人排錯使用。
- **將修圖計畫套用至選取照片（手動）**：讀取現有 `plan.tsv`，仍做身分與 baseline 檢查。

日常依範圍選擇「本地分析並套用選取照片（全部）」或「本地分析並套用選取照片（僅未修改）」。不要把手動匯出誤當成完整兩階段流程。
